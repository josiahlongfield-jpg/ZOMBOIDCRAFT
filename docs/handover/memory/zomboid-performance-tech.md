Started 2026-10-27 (thread "Make the game run smoothly", branch claude/project-thread-u0is1s). Josiah: with nearbyCap 80 / groups 8-16 / interval 4 s, FPS dropped to ~20 and felt choppy, so drawing is the main cost (RTX 4070, Sodium+Iris+Photon).

Why: each new zombie body (see [[zomboid-zbody-tech]]) is 1,300-3,100 quads rebuilt on the CPU every frame (vanilla zombie ~40), and Photon draws them again for shadows. Per outfit about 108 body quads; kit: ~35% SMALL, ~45% thinner than 1 px, ~10% 1-2 px, only ~60-120 bigger.

Built (commit 5c11efa5):
- client `zombie/body/ZDetail.java`: levels 0 full, 1 no SMALL, 2 no kit < 1 px, 3 no kit < 2 px. Each client tick it sorts walker distances: the nearest `performance.fullDetailZombies` (12) get 0 within look.zombieDetailDistance, the nearest `midDetailZombies` (32) get 1, the rest 2, past `simpleZombieDistance` (40) 3. Distances are divided by the zoom (options fov / camera fov), so a 4x scope keeps far targets detailed (Josiah's worry: "dont want them seeing a bunch of vanilla zombies"; the simplest level is still the new body, never vanilla). Iris shadow pass (IrisApi.isRenderingShadowPass by reflection) uses 3, or 2 up close, if `simpleZombieShadows`.
- ZBodyLayer.emit folds pose.pose() into the bone matrices once per bone (raw addVertex). WalkerRenderer caches zbody texture Identifiers per outfit.
- Server: InvestigateNoiseGoal re-plans only if the noise is 3+ blocks from its destination, max once a second; walkers drop RemoveBlockGoal (turtle egg hunt) and the Turtle target; MobMixin serverAiStep runs 1 in 4 ticks for idle walkers (no target, no heardAt, navigation done) beyond `performance.idleThinkDistance` (32, 0 = off).

Round 1 result (Josiah 06:55): ~20 -> ~30 FPS, "im sure we can do better". Round 2 (playtest 5de1ba3): tools/zombies/cull.py strips kit faces inside the body or a closed 6-face kit box on the same bone (7%, run after pack.py; the loose centre-only test showed holes, so keep the 5-point + whole-box rule; verify renderer in scratchpad only); ZBodyMesh.quads() lists per pass/LOD; normals to view space once per quad. Asked him for /tick query mspt and FPS with full/mid detail 0 to split drawing vs other cost.

Round 3 (Josiah 07:37 chose it: "zombies within shooting range are detailed", far ones can be rough in the dark rain): baked far bodies, playtest b81bdf9. tools/zombies/bake_low.py -> zbody/<outfit>_low.bin + textures/entity/zbody/low/<outfit>.png (1024x256 atlas, body faces get own patches since the skin shares texels; skin pre-tinted by BODY_TINT, clothes ray-painted from the same bone; keeps kit >= 2 wide or > 0.6 off the body). ~280 quads vs ~2,100. Used at ZDetail level >= 2 and all shadows; performance.bakedZombies toggles; midDetailZombies default 20 (DEFAULTS 3 upgrade). cull.py skips *_low. Preview tool tex.py was scratchpad only.
